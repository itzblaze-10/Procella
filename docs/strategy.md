# Strategy — three strategists, two rounds, five ideas

Three independent strategists argued the challenge, then rebutted each other with facts we verified
in between (POWER CORS, annual-mean key 13, solar record start, ORNL CORS).

| Strategist | Stance | Won | Conceded |
|---|---|---|---|
| Scientist | Rigor and judging | 3-state honest verdict, autocorrelation handling, minimum record gate, start-year sensitivity | Cut block bootstrap, FDR maps, Monte Carlo power; dropped the solar brightening demo |
| Product | Story and demo | Case-file layout, Twin Cases as hero, "Watch an example" | Pre-baked pairs were stories, not results; binary REAL stamp was dishonest; AI must be rule-based |
| Engineer | Feasibility | Static SPA, live POWER plus snapshots, hand-rolled stats tested against pymannkendall | Autocorrelation is in scope; ORNL can run live; per-variable start years |

## The five ideas, ranked

### 1. Case Files: a verdict-first detective flow (the spine)
Every investigation ends in a case file with four answers: WHAT is changing, WHERE (the box the
user chose), HOW MUCH (rate per decade with a 95% confidence interval), and WHAT WE CAN SAY.
The last answer has three honest states, never a binary stamp:
- **Detected** (trend significant),
- **Not detectable yet** (no significant trend; a longer record may change that),
- **Too short to judge** (record under the minimum-length gate).
A "Can I trust this?" panel shows start/end-year sensitivity so users see how fragile a trend is.

### 2. Twin Cases: opposite trends from one process (the hero demo)
Split screen, same variable, two regions, same method. Directly answers the brief's contrast theme.
Candidate pairs (all from live POWER, annual or deseasonalised, 1981 to latest full year):
- Precipitation: central Sahel (13N, 2E) vs central Chile (35S, 71W).
- Temperature T2M: Svalbard (78N, 16E) vs Southeast US (33N, 87W).
**None of these is a promised result.** Screen 6 to 8 candidate pairs through the real pipeline and
keep the two that hold up. Claim "opposite" only when both confidence intervals exclude zero with
opposite signs; otherwise say "slopes not distinguishable".

### 3. A statistics engine we can prove
Hand-rolled TypeScript, about 215 lines:
- monthly anomalies (remove the seasonal cycle), seasonal Mann-Kendall, Sen's slope with confidence interval,
- Hamed-Rao autocorrelation correction, Pettitt change-point check, minimum 20-year guard (warn under 15).
Tested against committed fixtures generated by `pymannkendall` (`original_test`, `seasonal_test`,
`hamed_rao_modification_test`). Pettitt tested with synthetic step series. Show the passing test
in the demo. Dropped: block bootstrap, per-pixel FDR maps, Monte Carlo power estimate.

### 4. Offline-proof architecture
Static React SPA on Vercel or Cloudflare Pages. No backend, no login-walled source.
- Live NASA POWER with an 8-second timeout, then localStorage cache, then committed snapshot JSON.
  A visible badge reads "Live NASA POWER" or "Cached snapshot (date)".
- Bundled world-atlas TopoJSON as the region picker (map tiles die with wifi).
- Service worker precaches app shell and snapshots; self-hosted fonts; no CDN scripts.
- ORNL MODIS NDVI as a second-tier case, labelled "greenness change 2000 to present".
- Backup screen recording of the demo.

### 5. Guided leads and a "Watch an example" mode (the educational layer)
For students: about 8 pre-written lead cards (news-style prompts or region types: desert, rain
forest, estuary, city) mapped to variable, region and period, stored as static JSON. A fixed-template
engine writes the plain-English verdict from the computed numbers, so nothing can hallucinate.
Plain-English variable glossary. "Watch an example" plays from snapshots only, so it works offline.
No live LLM calls (key would leak from a static site and adds a failure point). Label it "suggested
leads", and only call it AI if a model wrote the card text offline and we say so.

## Rejected, with reasons

- **FastAPI backend with pymannkendall:** cold starts and a second failure point on stage.
- **Giovanni / AppEEARS / OPeNDAP integration:** login walls and async queues eat the weekend.
- **Gridded significance maps with FDR:** heavy API volume, spatial autocorrelation caveats.
- **Live LLM suggestions:** key exposure, latency, hallucinated variables.
- **Solar brightening vs dimming headline:** POWER solar record starts after 1981 and the post-2000
  window is not the 1980 to 2000 story in the literature.

## Proposed split for two people (no shared files)

- **Partner A, data and stats:** `src/lib/` (`stats/`, `power.ts`, `modis.ts`, `types.ts`),
  `scripts/` generators, `tests/`, `public/snapshots/`.
- **Partner B, product UI:** `src/ui/`, `src/App.tsx`, map, charts, theme, copy.
- **Contract:** A publishes `src/lib/types.ts` (`Series`, `TrendResult`, `TrustFlags`) in the first
  30 minutes. B builds against mock data until A's modules land.

## Build order, first 8 hours

1. Scaffold Vite + React, deploy hello-world (proves hosting early).
2. `power.ts` with key-13, -999 and per-variable start-year handling; plot one series.
3. `stats.ts` plus fixtures; tests green before UI polish.
4. Snapshot generator and the Live/Cached badge; unplug wifi and verify.
5. Guided flow, glossary, region picker.
6. Case-file verdict, trust panel, Twin Cases.
7. Two scripted demos, mobile check, redeploy, backup recording.
